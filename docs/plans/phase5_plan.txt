3.2  New API Endpoint — Department Staff for Task Assignment
New endpoint for the internal task assignee selector:

GET /api/v1/tasks/staff/department
Query params: search: str (optional), size: int = 50
Auth: get_current_user

Logic:
  dept_id = caller.staff_profile.department_id
  SELECT users JOIN staff_profiles ON users.id = staff_profiles.user_id
  WHERE staff_profiles.department_id = dept_id
    AND users.is_active = TRUE
    AND users.id != caller.id  -- exclude self
    AND (search IS NULL OR
      LOWER(first_name || ' ' || last_name) LIKE '%' || LOWER(search) || '%'
      OR LOWER(staff_code) LIKE '%' || LOWER(search) || '%'
    )
  LIMIT size

Response: { data: [{ user_id, first_name, last_name, staff_code, job_title }] }

Phase 4 — External Task → Project Automation Engine

4.1  Core Design Principle — Projects Are No Longer Manually Created
After this phase is implemented:
The POST /api/v1/projects endpoint is DEPRECATED for direct use. It continues to exist for backward compatibility but is marked as legacy. The projects module UI is refactored to be read-only — no "Create Project" button.
All new projects are generated automatically by: (a) External task creation, (b) External app integrations (Sales, HR, Field, Inventory, Integration modules)
The task engine is the sole project creation gateway for all new operations

4.2  External Task Creation Flow — Step by Step
When a user creates a task with task_scope="external":
Backend receives POST /api/v1/tasks with task_scope="external" and department_id (target dept)
Validate target department exists and belongs to tenant
Create Task record with task_scope="external", pipeline_stage="backlog"
Generate project ticket number: PRJ-YYYY-NNNN (same sequence as before but auto-only)
Auto-generate Project record:
name = task.title
project_type = "external"
source_task_id = task.id
auto_generated = TRUE
department_id = payload.department_id (target dept)
owner_id = caller.id
due_date = derived from task.deadline
pipeline_status = "not_started"
Update task.project_id = new_project.id
Create TaskDeptRouting record: task enters target dept as routing_order=1
Fire notifications (Phase 6 — dept-wide alert to target department)
Write audit log: action="external_task_created_project"
Return response: { task: {...}, project: {...} }

4.3  Auto-Project Generation Service
New file: backend/app/modules/projects/auto_generator.py

class ProjectAutoGenerator:

  async def generate_from_task(
    self, db: AsyncSession,
    task: Task,
    caller: User,
    source_app: str | None = None,
  ) -> Project:
    """
    Called whenever an external task is created.
    Also called by external app triggers (Sales, HR, etc.)
    """
    ticket = await _generate_project_ticket_number(db)
    project = Project(
      name=task.title,
      description=task.description,
      project_type="external",
      source_task_id=task.id,
      auto_generated=True,
      source_app=source_app or "task_engine",
      department_id=task.department_id,
      owner_id=task.created_by,
      due_date=task.deadline.date() if task.deadline else None,
      ticket_number=ticket,
      tenant_id=task.tenant_id,
      pipeline_status="not_started",
    )
    db.add(project)
    await db.flush()
    task.project_id = project.id
    return project

project_auto_generator = ProjectAutoGenerator()

Phase 5 — Department Workflow & Manager Assignment Logic

5.1  Initial Department Ownership
When an external task/project arrives in a department:
The task is initially unassigned (assignee_user_id = NULL)
The task shows in the inbox of: Department Manager, Team Lead, Admin, Workflow Supervisor
These users see the task in a dedicated "Department Inbox" view on their dashboard
A SYSTEM notification is sent to all users with manager/lead/admin roles in that department
The task remains in "backlog" pipeline stage until explicitly assigned

5.2  Who Can Assign a Department Task
Assignment permission check logic — only these users can assign an unassigned external task:

async def check_can_assign(caller: User, task: Task) -> bool:
  # Must be in the task's target department
  if caller.staff_profile.department_id != task.department_id:
    return False
  # Must have manager/lead/admin role (level >= 3)
  if caller.role.level >= 3:
    return True
  # OR be explicitly tagged as workflow supervisor
  if caller.staff_profile.approval_authority_level >= 2:
    return True
  return False

5.3  Assignment API Endpoint
POST /api/v1/tasks/{id}/assign

    3. Create TaskAssignmentLog(assignment_type="reassign")
    4. Notify new assignee
    5. Notify old assignee of reassignment
    6. Write audit log
